# UA-DE Navigator — краткий контекст для будущих чатов

Состояние на 30.10.2026. Рабочий репозиторий: `avk-76/ua-de-navigator`. Публичная тестовая веб-версия собирается в `docs/`; сам GitHub и публикация Pages — разные этапы. Пользователь выбрал GitHub как основное место хранения изменений, онлайн-проверку сценариев и резервную копию по отдельной команде.

## Что сделано

- Модуль «Маршрут» начал проверять желаемый город для первого сценария: люди из Украины, претендующие на временную защиту по §24. Вводятся статус §24, место проживания, нужда в жилье и средствах, ограничение проживания, жильё/семья/работа/учёба/медицинское основание именно в целевом городе и доказательства.
- Для Berlin, München, Hannover и Leipzig есть датированные официальные ссылки и осторожный вывод: есть основание обратиться, нужна проверка документов или город не гарантирован при распределении. Альтернативный город проверяется с новыми данными; доказательства для первого города не переносятся автоматически.
- Семейные карточки маршрута различают людей и ведомства; для Überlingen применяются Stadt Überlingen и Bodenseekreis. Статус источника означает доступность страницы, а не юридическую применимость.
- Существующие OCR письма в браузере, облачный ИИ и кабинет — отдельные части продукта; новая логика выбора города работает по правилам, без ИИ.

## Проверено и ограничения

- Локальные тесты логики маршрута прошли. В браузере проверен сценарий Berlin: §24, супруг с документами; результат показывает основание для запроса, три альтернативы и официальные ссылки. OCR ранее проверен на изображении, текстовом и сканированном PDF.
- Нет автоматического поиска по всем официальным ресурсам и единого достоверного потока о свободных местах или решениях о распределении. Для остальных городов маршрут не обещает приём и направляет к официальному поиску ведомства. Правила четырёх городов нужно периодически пересматривать и указывать дату проверки.
- После публикации отдельно проверить реальную веб-версию, вход/кабинет, ИИ и серверную функцию. Обновление файлов GitHub не развёртывает Supabase Edge Function или миграции базы.

## Как продолжать

Менять исходники в `prototype/`, тестировать маршрут на вымышленных данных, собирать и проверять `docs/`, затем проверять опубликованную страницу. Следующий приоритет — источник актуальных официальных условий по городам и явный ответ «данных недостаточно» при отсутствии подтверждения приёма. Не утверждать, что земля принимает человека, только по наличию страницы или места первичного приёма.
